# Feature comparison

Notes, sources, and simulators left off the table in [README.md](README.md).

Simulators are the public tools under [Simulators and emulators](https://github.com/uzh-rpg/event-based_vision_resources#simulators-emulators), plus [Prophesee](https://github.com/prophesee-ai/openeb)'s Metavision video-to-event simulator, which that list does not include. The table stops at vid2e. Simulators after it in the check-count ordering have fewer checks, or the same number and an older last push, and are left off. Each name links to the repository that was read. v2e is this repository.

Readout nonideality means the address-event bus: a finite time per event, row arbitration, or a clocked row scan that moves the timestamp away from the pixel's decision time.

HVS/DAVIS output means the simulator emits intensity frames and events together, as a hybrid sensor does. A check here is not given for showing the input video next to the events.

## Notes

**v2e.** Shot noise, leak events, cutoff, threshold mismatch, and refractory period are in `v2ecore/emulator.py`. The lowpass time constant shortens as intensity rises (`low_pass_filter` in `v2ecore/emulator_utils.py`). Multiple events in one frame interval are stacked on `linspace` steps in that file.

**ESIM.** README feature list, plus `event_camera_simulator/esim/src/event_simulator.cpp` (C+, C−, Gaussian `sigma_Cp` / `sigma_Cm`, refractory period, linear interpolation of log intensity) and `data_provider_online_simple.cpp` (adaptive sampling). There is no shot-noise, leak, or photoreceptor-lowpass term in the event simulator. RPG later reused this event model in [vid2e](https://github.com/uzh-rpg/rpg_vid2e): `esim_torch` runs the same contrast-threshold loop on video after frame interpolation.

**Prophesee.** Metavision Core ML, in [OpenEB](https://github.com/prophesee-ai/openeb). The [API](https://docs.prophesee.ai/stable/api/python/core_ml/video_to_event.html) says the simulator follows Gehrig et al. (vid2e) and Hu, Liu, and Delbruck (v2e). The copy scored here is the `main` tree, CMake `project(metavision VERSION 5.2.0)`. CPU class `EventSimulator`; GPU class `GPUEventSimulator`.

**vid2e.** README and `esim_torch/README.md`. vid2e is the video front end for the ESIM event model. SuperSloMo upsamples the frames, with FILM added later, and `esim_torch` (a PyTorch and CUDA rewrite of ESIM's event loop) emits the events. It exposes contrast thresholds and a refractory period. ESIM's Gaussian threshold noise (`sigma_Cp` / `sigma_Cm`) is absent from that API.

**IEBCS.** README example parameters, and `src/dvs_sensor.py`. `tau_p = tau * 1e3 / (img + 1)` is the intensity-dependent log-front-end time constant. Background events come from `check_noise` or `check_noise_hist`. `src/arbiter.py` is the readout model. In `examples/00_video_2_events/1_example_video_to_events.py` the synchronous arbiter is constructed and `ea.process` is commented out, so a default run does not delay timestamps.

**EssacSim.** Same repository as the EVIS technical report. README `DVSNoiseCfg`: threshold mismatch, leak events, shot events, hot pixels, refractory time, and intensity-dependent photoreceptor bandwidth. The default configuration is a clean sensor. Warp uses renderer motion vectors. Package version is `0.1.0` in `pyproject.toml`.

These entries are on the same resources page. They are omitted because there is no public general-purpose simulator to score, or the repository is not an event-camera model.

- Katz et al. 2012, behavioural emulation. The page links a PDF, not a maintained simulator.
- InteriorNet (2018). A rendered dataset. The simulator is not released as a tool.
- Nehvi et al. 2021, differentiable event stream simulator. Project page and paper. No public code found.
- Gava et al. 2022. An air-hockey latency study. The linked tree is that study, not a general simulator.
- Gu et al. TPAMI 2024, invertible conditional normalizing flow. Paper only in the list.
- EvDNeRF (WACV 2024). A dynamic NeRF that reconstructs events. The repository README says simulated-data generation is still "coming soon."
- Lu et al. 2025, hybrid event-frame sensor model. arXiv only in the list.

The [synthetic data generators](https://github.com/uzh-rpg/event-based_vision_resources#synthetic-data-generators) section (Arcade Learning Environment wrapper, Text-to-Events) is a different heading and is not in the table.
